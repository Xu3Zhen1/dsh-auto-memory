# 提案：`iter5ReadMode` 嵌套扁平化（KISS −11 @ 旧口径 / −3 @ 当前口径）

**状态**：草稿 · **日期**：2026-11-12 · **性质**：`flatten-client` 的首片探针

## 问题

`lib/client.js` 的 `iter5ReadMode()` 把「从 localStorage 解析初始明暗模式」整段内联在
**四层嵌套**（`if / try / if-else / if`）里，触发 `KISS-C1`（嵌套深度 ≤ 3）共 **11 处**违例。

可观察的坏事不是"难看"，而是：这段代码承载 **H36 双向镜像契约**（`dam-skin-theme` ↔
`dsh-auto-memory.appearance.v1` 两键恒等）。四层嵌套下，三个分支的**副作用差异**
（哪个分支写回、哪个不写、写什么值）埋在缩进里，改一个字符就可能让某一分支静默不再镜像。
而这类缺陷**不会崩**——只会表现为「切换后另一处没跟上」。

## 变更范围

| 文件 | 动作 |
| :-- | :-- |
| `skins/iter5/style-choice.js` | 抽出同级纯函数 `iter5ResolveStoredMode()`；`iter5ReadMode()` 减为「缓存判定 + 调用 + 赋值」 |
| `lib/client.js` | **由生成器重建**（不手改；`ITER5-GENERATED` 区内） |

## 非目标（YAGNI · 强制）

| 不做的事 | 为什么不做 |
| :-- | :-- |
| **不手改 `lib/client.js`** | 该段落在 `ITER5-GENERATED` 区内（L13522–16944），手改会被下次生成覆盖，且 `--check` 必红 |
| 不改三个分支的**语义**（含 `iter5NormalizeMode(legacy)` 这个看似多余的表达式） | 「首次升级路径传 legacy 而非 saved」虽结果同为 `system`，但保留上游 3.2.x 的原始表达式形状。**纯扁平化不改形** —— 见下方「等价变异」记录 |
| 不合并 `iter5ReadStyle` / `iter5SetMode` 等相邻函数 | 它们不在本簇；只做这一处，控制 diff 便于逐行审查 |

| 不改 `ITER5_LEGACY_THEME_KEY` / `ITER5_MODE_KEY` 常量 | 键名是磁盘契约 |

## 验收标准

1. `KISS-C1` 全量 **2092 → 2081**（旧口径 `sdd-guard ≤311a54c`，Δ **−11**）；
   **当前口径（`≥88eefd3`，该 commit 重写 `nestingDepth`）为 4193 → 4190，Δ −3**。
   实测两版均为负，验收结论不变 —— 但**引用本数字必须带口径**，否则相差 2 倍不可复核。
2. `DRY-C1` 保持 **22**（不变差）；`YAGNI-C1` 保持 0。
3. **生成器同步**：`--check` 报 `SYNC-OK`。
4. **行为逐条不变**：改前（基 `e415450c` 源文件）vs 改后，**17 个用例 0 差异**，
   覆盖：空存储 / 合法值 / 垃圾值 / 空串 / 仅 legacy / legacy+已存值 / `'auto'` 特例 /
   legacy 空串 / 拒绝存储抛错 / 缓存语义（第二次读不再碰存储）。
   **且比对含镜像写回的副作用**（`localStorage` 最终内容逐项相同），不只比返回值。
5. 全量回归（分母 460）失败集不新增。

## ★ 必须声明一：生成器孤儿行停机（exit 2），本次用 `--force`，理由与验证

无 flag 实跑被 R2 拦下，报 **14 行「只存在于 lib/client.js」**。逐行核对：

| 行 | 内容 | 判定 |
| :-- | :-- | :-- |
| L13583–13595（**11 行**） | 正是本片删掉的旧内联段 | **预期内**：源已改、产物待重建，旧产物自然多出这些行 |
| L18672 | `} else {` | **假阳性**：括号行 |
| L19915 | `}` | 同上 |
| L20017 | `}` | 同上 |

**为什么括号行是假阳性**：`orphanedLines()` 是**整行多重集比对**（带计数配对）。
本片删掉 11 行含 `if`/`}`/`{` 的行后，括号行的计数配平发生位移，于是文件中**其它位置**
的纯括号行被"借走"配平 ⇒ 报为孤儿。它们不是真内容丢失。

**决定性验证（不是靠推理，是靠 diff）**：
`git diff -- lib/client.js` 全部 51 行变更**逐行核过** ——
只有 `@@ -13577` 这一个 hunk（`+37 / −14`），即只有 `iter5ReadMode` 那一段，
**文件中其它任何位置零改动**。⇒ 那 3 行括号确实没丢。

> 纪律：`--force` 是「明确放弃这些行」的语义。本次能用它，是因为**先证明了那 14 行里
> 没有真内容**（11 行是被替换的旧实现 + 3 行假阳性括号），并用 diff 逐行验证了改动范围。
> 若 diff 出现第二个 hunk，就必须停下。

## ★ 必须声明二：一个负控是**行为等价变异**，不作证据

四个变异中三个真红，一个不红（已定性）：

| 变异 | 结果 | 说明 |
| :-- | :-- | :-- |
| legacy 分支**不镜像写回** | 🔴 真红（8 处差异） | ✔ 有效证据 |
| 消费 saved 时**不归一化** | 🔴 真红（1 处：`saved=垃圾值`） | ✔ 有效证据 |
| legacy 判定 `!= null` → **truthy** | 🔴 真红（1 处：`legacy 空串 + saved=dark`） | ✔ 有效证据 |
| 首次升级路径**传 saved 而非 legacy** | ⚪ **不红** | **行为等价**：该分支下 `legacy` 必为 `null`，`iter5NormalizeMode(null)` 与 `iter5NormalizeMode(saved=null)` **都是 `'system'`** ⇒ 无可观测差异。故不作为判据有效的证据 |

⇒ 结论：本片的行为判据**有真鉴别力**（三条独立变异各自命中不同分支），
但**不能**声称"任何语义改动都会被抓住"—— 那条等价变异就是反例。

## 附：这是 `flatten-client` 的探针片

目的不只是减 11 处，而是验证整条流水线可用：

| 环节 | 本片实测 |
| :-- | :-- |
| 改源 → 生成 → `--check` 绿 | ✅ |
| 孤儿行停机是否会误伤 | ✅ 会报，但已证明可定性（11 真 + 3 假阳性括号），且用 diff 兜底 |
| 既有行为测试是否覆盖 | ✅ `smoke-test-style-variants.mjs` **真跑** `iter5ReadMode`（vm + localStorage 桩），不是源码文本断言 |
| 三处哈希锁 | ✅ 全部复绿（`iter5-skin` / `settings-archive-interval` / `r26`） |
| 负控 | ✅ 3/4 真红，1 个已定性为等价变异 |

⇒ 结论：**流水线可用，但 `KISS-C1 ≤ 3` 对 `client.js` 在工程上不可达**，理由不是「违例多」而是**斜率太慢**：

| 项 | 旧口径 `≤311a54c` | 当前口径 `≥88eefd3` |
|:--|--:|--:|
| `client.js` 违例（HEAD `8a62ebdb`） | **275** | **1974** |
| `client.js` 行数（HEAD `8a62ebdb`） | 19,943 | 19,943 |
| 本片边际（`e415450c` → `cf8c7a0e`） | 286 → 275（**−11**） | 1977 → 1974（**−3**） |

按本片实测斜率（当前口径 **3 处/片**），清完 1974 处需 **658 片**（1974 ÷ 3，**乐观上界**：假定每片都只降 3 且无连锁收益）。

> ★这是**粗算**，不是精算 —— 真去清时，一处扁平化常连带压低邻近若干处，斜率会变。但它足以说明量级：
> **两位数片是可行，三位数片（658）不是。** 若换成旧口径 275 处 ÷ 11 = 25 片，那确实是「慢但可达」——
> **这正是为什么必须标口径：同一个文件，一个口径说「25 片可达」，另一个说「658 片不可达」。**

> ★注意口径：**当前口径下 `client.js` 是全仓嵌套最深的文件（1974，反超 `index.js` 的 1434）**；
> 旧口径下它只有 275（`index.js` 才是 1483）。⇒ 将来真要压 KISS，**第一刀该打 `client.js` 而非 `index.js`**。

后续只能按「有边界地降债」推进，不宜当作一次性战役。
