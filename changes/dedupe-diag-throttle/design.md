# 技术设计：消除 evidence-store ↔ shadow-host 的 4 处跨文件重复块（诊断节流）

## 方案摘要

新建零依赖 `lib/diag-throttle.js`，承载模块级节流表与 `shouldReportDiag(key)`。
`evidence-store.js` 与 `shadow-host.js` 改为具名导入，删除各自私有副本。
函数体逐字节照搬。

## 复用清单（DRY · 强制）

| 现有模块路径 | 提供什么能力 | 本次如何复用 |
| :-- | :-- | :-- |
| `lib/evidence-store.js` | 证据事件存储；内含节流表私有实现 | 迁出该实现，改为导入；其余不动 |
| `lib/shadow-host.js` | 影子检索宿主；内含同款节流表 | 同上 |
| `lib/index.js` | 宿主主体；含 `diagThrottled` 同语义实现 | **不适用（刻意不并入）**：该文件被 r26 哈希锁钉住，并入须重钉锁，会把纯提取与锁值变更混进同一 diff。已在提案非目标表登记 |
| `lib/team-primitives.js` | 上一片新建的安全访问原语 | **不适用**：职责不同（那是取值原语，这是节流状态机）；混进同一模块会变成新的垃圾场 |

## 新增依赖（KISS · 强制）

无。`lib/diag-throttle.js` **零 import**。

## 接口契约

进程内单包插件，无前后端边界。契约真源为节流判据的唯一实现处：

| 契约真源路径 | 承载什么 | 谁引用 |
| :-- | :-- | :-- |
| `lib/diag-throttle.js` | `shouldReportDiag(key)`：模块级窗口表，首条立即放行、窗口内压制、超窗再放行；计时失败**放行**（fail-open） | `lib/evidence-store.js`、`lib/shadow-host.js` |

**key 隔离契约**：调用方必须以子系统前缀命名 key（现为 `evidence:*` / `shadow:*`）。
共享一张表是**有意**的：两模块的注释都写着「语义同 index.js 的 diagThrottled」，
说明"同一条诊断共享同一窗口"是本仓既有语义。前缀保证不同子系统互不压制。

## 结构决策

**为什么共享一张表而不是每模块一张：** 既有实现里两处表虽然物理分离，但语义注释完全一致
（同一窗口、同一"首条立即透出"）。合并成一张 + 前缀命名，把"应该共享"变成结构事实；
若将来真的需要独立窗口，那时应显式传参而不是靠"各抄一份"。

## 刻意不采用的模式

| 模式 | 为什么不采用 |
| :-- | :-- |
| 做成 class / 工厂（每实例一张表） | 现有语义是**模块级共享**（注释明写「表放模块级而非实例级/闭包级 ⇒ 同进程多实例共享」）。改成实例级会改变节流行为：多实例各自持表 ⇒ 同一个 key 被各自放行一次，刷屏更严重 |
| 把窗口做成可配置参数（默认 300s） | 当前无第二处需要别的值；加参数会诱导未来传任意值，把一处语义裂成 N 处 |
| 用时间戳数组做滑动窗口 | 现有语义是"每个 key 只记最近一次放行时刻"（不是滑动窗口）。改算法＝改行为，不属纯提取 |

## 验证方式

1. **行为对拍**：注入可控 `Date.now`（或在同一进程内按真实时间推进），验证
   ① 同 key 首次 `true`；② 窗口内再调 `false`；③ 超窗后 `true`；④ `Date.now` 抛错时 `true`。
2. **机器判据**：`sdd-guard check --only DRY-C1,KISS-C1`，本文件对归零、全量只减不增。
3. **回归**：`node tools/run-smoke.mjs`（分母 457），失败集不新增。
4. **负控**：把窗口常量改 0（永不压制）⇒ 新判据必须红；变异体须自证真应用且 `node --check` 通过。
